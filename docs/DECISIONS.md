# Decisions

One line of reasoning per decision. Newest at the bottom.

| #   | Decision                                                                                                                                                                      | Reason                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | Product name **Crewboard**.                                                                                                                                                   | Short, neutral, describes a board for a small crew, not a well-known product.                                               |
| 2   | Palette: deep teal board, slate column panels, white cards, amber focus ring.                                                                                                 | One strong board colour that is clearly not Trello's blue; teal-on-white and slate text pass WCAG AA.                       |
| 3   | Task dialog is a route (`#/board/tasks/:id`).                                                                                                                                 | Gives deep links to a task that survive a hard refresh with hash routing.                                                   |
| 4   | Settings is a page (`#/settings`), not a modal.                                                                                                                               | Simpler focus handling and a natural deep link; the spec only asks for "minimal" settings.                                  |
| 5   | No state-management library; React context + a `useBoardData` hook.                                                                                                           | Three resources and one board do not need more.                                                                             |
| 6   | Positions are dense integers (0..n-1) per column, re-numbered by the server on every move/create/delete.                                                                      | Simple, deterministic, easy to test; the data set is tiny.                                                                  |
| 7   | Mock latency is set by `VITE_MOCK_LATENCY` ("min,max" ms); unit tests pass 0 directly.                                                                                        | Keeps the demo's loading states real while letting tests run fast.                                                          |
| 8   | A failure-injection hook (`?failMoves=1` in the URL, read by the composition root and passed to the mock server; no UI code knows about it) to test move rollback end to end. | The spec requires a visible rollback; without a real network there is no other way to force a failing move in the browser.  |
| 9   | Commits use the GitHub profile name and the `users.noreply.github.com` address.                                                                                               | Keeps personal email addresses out of public commit metadata.                                                               |
| 10  | Create a task through a dialog opened by each column's "Add a card" button, not an inline composer.                                                                           | The spec asks for title, description and assignee at creation; a dialog fits all three accessibly and reuses the edit form. |
| 11  | "My tasks" filters client-side from the full task list; `GET /tasks?assignee=me` is implemented and tested in the API but not used by the board.                              | Drag and drop needs the full column order to compute positions while filtered; one list keeps both views consistent.        |
| 12  | Task mutations are queued and sent one at a time.                                                                                                                             | The mock's random latency could otherwise apply two quick moves in the wrong order.                                         |
| 13  | System UI font stack as the one typeface family.                                                                                                                              | No external font requests, fast first paint, native look on each platform.                                                  |
| 14  | `deploy.yml` reuses `ci.yml` (`workflow_call`) as its first job.                                                                                                              | Deploys only happen after the same checks pass, with one definition of those checks.                                        |
| 15  | Token cost uses API list prices for global routing fetched on the day; Haiku at the ≤100k-token tier.                                                                         | Matches what the logs record (`inference_geo: global`); see `docs/metrics/pricing.json`.                                    |
| 16  | React Router data router (`createHashRouter`) instead of `<HashRouter>`.                                                                                                      | Needed for `useBlocker`, so browser Back asks before discarding unsaved dialog edits.                                       |
| 17  | `PATCH /tasks/:id` takes an optional `expectedUpdatedAt` and returns 409 on a stale edit (added to the contract).                                                             | Two people (or tabs) editing one task must not silently overwrite each other; smallest version of optimistic concurrency.   |
| 18  | The mock stores each write before its simulated latency and processes requests one at a time.                                                                                 | Matches a real server: a sent request survives a reload; avoids lost updates between concurrent requests.                   |
| 19  | Closing a task dialog replaces its history entry with the board.                                                                                                              | Back never reopens a closed dialog, and closing never depends on history entries the router did not create.                 |
| 20  | In-memory storage fallback with a visible notice when the browser blocks `localStorage`.                                                                                      | A blank page is worse than a demo that forgets on tab close.                                                                |
